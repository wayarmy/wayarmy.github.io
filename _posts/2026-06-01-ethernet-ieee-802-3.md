## 1. Giới thiệu — Tại sao cần biết Ethernet?

### Ví dụ đời thường: Phòng họp và quy tắc phát biểu

Hãy tưởng tượng bạn đang ở trong một **phòng họp lớn** với 20 người. Mọi người muốn phát biểu nhưng chỉ có **một microphone duy nhất** được truyền quanh bàn. Quy tắc là:

1. **Nghe trước khi nói** — Nếu ai đó đang nói, bạn phải đợi im lặng
2. **Nếu hai người nói cùng lúc** (collision) — cả hai dừng lại, đợi một khoảng thời gian ngẫu nhiên rồi thử lại
3. **Mỗi phát biểu có cấu trúc** — Bạn phải nói rõ "Tôi là Hùng (nguồn), gửi cho chị Lan (đích), nội dung là: dự án A hoàn thành rồi (data)"
4. **Người nhận xác nhận** — Chị Lan gật đầu (acknowledgment)

Đó chính là cách Ethernet ban đầu hoạt động! Phòng họp là **network segment**, microphone là **shared medium** (cáp đồng trục ban đầu), quy tắc phát biểu chính là **CSMA/CD**, và cấu trúc phát biểu chính là **Ethernet Frame**.

### Concrete scenario: "Hãy tưởng tượng bạn đang..."

Hãy tưởng tượng bạn đang mở laptop, gõ `google.com` vào trình duyệt. Trong vòng **chưa đầy 1 giây**, hàng chục Ethernet frames đã được tạo ra, gửi đi, và nhận lại. Mỗi frame mang một mảnh thông tin — DNS query, TCP handshake, HTTP request — tất cả đều được "đóng gói" trong Ethernet frames để truyền từ laptop qua cáp mạng đến router/switch.

**Nếu không có Ethernet**, máy tính của bạn giống như một người đứng giữa phòng hét to mà không ai hiểu — không có quy tắc giao tiếp, không có cách xác định ai nói với ai, không có cách phát hiện lỗi.

### Vấn đề Ethernet giải quyết

| Vấn đề | Giải pháp của Ethernet |
|---------|----------------------|
| Làm sao nhiều máy dùng chung 1 dây cáp? | CSMA/CD — lắng nghe trước khi nói |
| Làm sao biết data gửi cho ai? | MAC Address trong Frame Header |
| Làm sao biết data bị lỗi khi truyền? | FCS (Frame Check Sequence) — CRC-32 |
| Làm sao thống nhất tốc độ giữa 2 thiết bị? | Autonegotiation |
| Làm sao phân biệt loại data bên trong? | EtherType field |

## 2. Ethernet là gì? — Giải thích cho người không biết IT

### Định nghĩa đơn giản

**Ethernet** là một bộ **quy tắc giao tiếp** (protocol) cho phép các thiết bị (máy tính, điện thoại, máy in, TV thông minh...) nói chuyện với nhau qua **dây cáp mạng** (hoặc cáp quang). Nó quy định:

- **Định dạng "phong bì"** — data phải được đóng gói thế nào (frame format)
- **Quy tắc gửi** — khi nào được gửi, phải làm gì nếu có xung đột (media access control)
- **Tốc độ** — nhanh bao nhiêu (10 Mbps → 400 Gbps)
- **Loại dây** — dùng dây gì (đồng, quang, twisted pair)

### Analogy 2: Hệ thống bưu điện

Nếu Internet là hệ thống bưu điện toàn cầu, thì Ethernet là **quy tắc vận chuyển thư trong cùng một thành phố** (LAN — Local Area Network):

```
┌─────────────────────────────────────────────────────────┐
│                  HỆ THỐNG BƯU ĐIỆN                       │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  Bưu điện = Switch         Phong bì = Ethernet Frame    │
│  Địa chỉ nhà = MAC Address Mã bưu chính = IP Address   │
│  Xe chở thư = Cáp mạng    Nội dung thư = Payload/Data  │
│  Dán tem = EtherType       Niêm phong = FCS (checksum)  │
│                                                          │
│  Thành phố = LAN           Liên tỉnh = WAN (Internet)   │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### ASCII Diagram: Vị trí Ethernet trong mô hình mạng

```
┌─────────────────────────────────────────────────────────────┐
│  Application Layer (HTTP, DNS, SMTP...)                      │
├─────────────────────────────────────────────────────────────┤
│  Transport Layer (TCP, UDP)                                  │
├─────────────────────────────────────────────────────────────┤
│  Network Layer (IP — IPv4, IPv6)                             │
├──────────────────────────────────────────────┬──────────────┤
│  Data Link Layer ← ETHERNET Ở ĐÂY!         │ LLC (802.2)  │
│  ┌────────────────────────────────────────┐  │              │
│  │ MAC Sublayer — Frame, CSMA/CD, Addr   │  │              │
│  └────────────────────────────────────────┘  │              │
├──────────────────────────────────────────────┴──────────────┤
│  Physical Layer (cáp, tín hiệu điện/quang, connectors)      │
└─────────────────────────────────────────────────────────────┘
```

Ethernet hoạt động ở **Layer 2 (Data Link)** và một phần **Layer 1 (Physical)**. Nó là "cầu nối" giữa tín hiệu vật lý trên dây cáp và dữ liệu logic (IP packets) ở lớp trên.

## 3. Ethernet Frame Structure — Cấu trúc "phong bì" dữ liệu

### Ví dụ đời thường trước khi vào kỹ thuật

Khi bạn gửi thư, phong bì cần có: tên người gửi, tên người nhận, tem (loại dịch vụ), nội dung bên trong, và seal (niêm phong để biết thư có bị mở ra không). Ethernet frame cũng vậy — mỗi "gói tin" trên mạng LAN đều có cấu trúc cố định.

### 3.1 Ethernet II Frame (DIX) — Phổ biến nhất hiện nay

Đây là format được dùng trong **99.9% mạng hiện đại** (theo RFC 894):

```
┌──────────┬─────┬────────────┬────────────┬───────────┬──────────────────┬─────┐
│ Preamble │ SFD │ Dest MAC   │ Src MAC    │ EtherType │ Payload          │ FCS │
│ 7 bytes  │ 1B  │ 6 bytes    │ 6 bytes    │ 2 bytes   │ 46-1500 bytes    │ 4B  │
└──────────┴─────┴────────────┴────────────┴───────────┴──────────────────┴─────┘
│←── Không tính vào frame size ──→│←──── Frame size: 64-1518 bytes ────────────→│
```

**Tổng kích thước trên dây:** 72 - 1526 bytes (bao gồm Preamble + SFD)

### 3.2 Chi tiết từng trường (field)

#### Preamble — "Tiếng gõ cửa" (7 bytes)

```
Bit pattern: 10101010 10101010 10101010 10101010 10101010 10101010 10101010
```

**Mục đích:** Giúp receiver **đồng bộ clock** (clock synchronization). Giống như khi ai đó gõ cửa "tuk-tuk-tuk" đều đặn — bạn biết có người đến và chuẩn bị lắng nghe.

**Tại sao cần đồng bộ clock?** Vì Ethernet dùng baseband signaling — tín hiệu chỉ là sóng vuông (high/low voltage). Receiver cần biết chính xác "bao lâu thì 1 bit" để đọc đúng data. Preamble cho receiver thời gian để lock vào tần số của sender.

#### Start Frame Delimiter (SFD) — "Bắt đầu nói thật" (1 byte)

```
Bit pattern: 10101011
```

Hai bit cuối `11` (thay vì `10` như preamble) báo hiệu: **"Frame thực sự bắt đầu từ byte tiếp theo!"**

#### Destination MAC Address — "Gửi cho ai?" (6 bytes)

Ví dụ: `FF:FF:FF:FF:FF:FF` (broadcast) hoặc `00:1A:2B:3C:4D:5E` (unicast)

- **Unicast**: Gửi cho 1 máy cụ thể
- **Multicast**: Gửi cho 1 nhóm máy (bit thấp nhất của byte đầu tiên = 1)
- **Broadcast**: Gửi cho TẤT CẢ máy trong LAN (`FF:FF:FF:FF:FF:FF`)

```
Cách nhận biết multicast:
  Byte đầu tiên: XX:XX:XX:XX:XX:XX
                  │
                  └── Bit LSB = 1 → Multicast
                      Bit LSB = 0 → Unicast
                      
  Ví dụ: 01:00:5E:XX:XX:XX → IPv4 Multicast
          33:33:XX:XX:XX:XX → IPv6 Multicast
```

#### Source MAC Address — "Ai gửi?" (6 bytes)

- **Luôn là unicast** — sender không bao giờ là broadcast/multicast
- Switch học source MAC để xây dựng MAC address table

#### EtherType — "Bên trong là loại gì?" (2 bytes)

| EtherType (hex) | Protocol | Giải thích |
|-----------------|----------|-----------|
| 0x0800 | IPv4 | Gói tin Internet v4 |
| 0x0806 | ARP | Hỏi "MAC address của IP này là gì?" |
| 0x86DD | IPv6 | Gói tin Internet v6 |
| 0x8100 | 802.1Q | VLAN tagging |
| 0x8847 | MPLS unicast | Label switching |
| 0x88CC | LLDP | Link Layer Discovery Protocol |
| 0x8863/0x8864 | PPPoE | PPP over Ethernet (ADSL) |

**Quy tắc phân biệt quan trọng:**
- Giá trị **≤ 1500 (0x05DC)** → đây là **Length field** (IEEE 802.3 frame)
- Giá trị **≥ 1536 (0x0600)** → đây là **EtherType** (Ethernet II frame)
- Khoảng **1501-1535** → không hợp lệ, không được sử dụng

#### Payload — "Nội dung thư" (46 - 1500 bytes)

- **Minimum 46 bytes**: Nếu data ít hơn 46 bytes, phải thêm **padding** (bytes 0x00) để đủ. Tại sao? Vì frame phải đủ dài (ít nhất 64 bytes tổng) để cơ chế collision detection hoạt động đúng.
- **Maximum 1500 bytes**: Đây là **MTU** (Maximum Transmission Unit) mặc định của Ethernet
- **Jumbo Frames**: Một số mạng data center cho phép payload lên đến 9000 bytes (MTU 9000) — gọi là Jumbo Frames

**Tại sao minimum 64 bytes (tổng frame)?**

Đây là câu hỏi hay! Trong 10 Mbps Ethernet ban đầu, segment dài tối đa 2500m. Tín hiệu di chuyển với tốc độ ~200,000 km/s trong cáp đồng. Thời gian round-trip:

```
Round-trip time = 2 × 2500m ÷ 200,000,000 m/s = 25 μs
Slot time = 51.2 μs (IEEE chọn để có safety margin)
Ở 10 Mbps: 51.2μs × 10,000,000 bps = 512 bits = 64 bytes
```

Nếu frame ngắn hơn 64 bytes, sender có thể gửi xong trước khi phát hiện collision — CSMA/CD sẽ thất bại!

#### FCS — Frame Check Sequence (4 bytes)

- Sử dụng **CRC-32** (Cyclic Redundancy Check)
- **Polynomial**: x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1
- Tính trên: Dest MAC + Src MAC + EtherType + Payload
- **Chỉ phát hiện lỗi**, KHÔNG sửa lỗi. Nếu FCS sai → frame bị drop silently

**Ví dụ đời thường:** Giống như số kiểm tra (check digit) trên mã vạch sản phẩm — nếu bạn gõ sai 1 số, máy quét báo lỗi ngay.

### 3.3 IEEE 802.3 Frame (với LLC/SNAP) — Ít dùng hơn

```
┌──────────┬─────┬────────┬────────┬────────┬─────────┬──────────┬─────┐
│ Preamble │ SFD │Dst MAC │Src MAC │ Length │ LLC/SNAP│ Payload  │ FCS │
│ 7 bytes  │ 1B  │6 bytes │6 bytes │2 bytes │ 3-8B   │ variable │ 4B  │
└──────────┴─────┴────────┴────────┴────────┴─────────┴──────────┴─────┘
```

Dùng trong STP (Spanning Tree Protocol), CDP (Cisco Discovery Protocol), và một số protocol cũ.

### 3.4 802.1Q VLAN Tagged Frame

```
┌────────┬────────┬────────┬───────────────────┬───────────┬─────────┬─────┐
│Dst MAC │Src MAC │ 0x8100 │ TCI (Tag Control) │ EtherType │ Payload │ FCS │
│6 bytes │6 bytes │ 2B     │ 2 bytes           │ 2 bytes   │ 46-1500 │ 4B  │
└────────┴────────┴────────┴───────────────────┴───────────┴─────────┴─────┘
                   │        │
                   │  ┌─────┴───────────────────────┐
                   │  │ PCP │ DEI │ VLAN ID (12 bit)│
                   │  │ 3b  │ 1b  │ 12 bits         │
                   │  └─────┴─────┴─────────────────┘
                   │
                   └── Tag Protocol Identifier (TPID)
```

- **TPID = 0x8100**: Đánh dấu đây là VLAN-tagged frame
- **PCP** (3 bits): Priority Code Point — QoS priority (0-7)
- **DEI** (1 bit): Drop Eligible Indicator
- **VLAN ID** (12 bits): Số hiệu VLAN (0-4095, usable: 1-4094)
- Maximum frame size tăng lên **1522 bytes** (thêm 4 bytes tag)

## 4. CSMA/CD — Cơ chế "ai được nói" trên shared medium

### Ví dụ đời thường: Cuộc họp không có moderator

Tưởng tượng 10 người ngồi quanh bàn tròn, không có ai làm chủ tọa. Ai muốn nói thì phải:

1. **Lắng nghe** (Carrier Sense) — Xem có ai đang nói không
2. **Nếu im lặng → nói** (Multiple Access) — Bắt đầu phát biểu
3. **Vừa nói vừa nghe** (Collision Detection) — Nếu phát hiện có người khác cũng đang nói cùng lúc → DỪNG LẠI
4. **Gửi tín hiệu "JAM"** — Hét lên "XIN LỖI CÓ TRÙNG!" để mọi người biết
5. **Đợi random** — Mỗi người đợi thời gian ngẫu nhiên khác nhau rồi thử lại

### 4.1 CSMA/CD Step-by-Step

```
┌──────────────────────────────────────────────────┐
│  Station muốn gửi frame                          │
└──────────────────┬───────────────────────────────┘
                   ▼
         ┌─────────────────┐
         │  Channel IDLE?  │──── NO ──→ Đợi + backoff
         └────────┬────────┘
                  │ YES
                  ▼
         ┌─────────────────┐
         │  Bắt đầu gửi   │
         │  frame          │
         └────────┬────────┘
                  ▼
         ┌─────────────────┐
         │  Phát hiện      │──── YES ──→ Gửi JAM signal (32 bits)
         │  collision?     │              │
         └────────┬────────┘              ▼
                  │ NO              ┌─────────────┐
                  ▼                 │  Tăng retry │
         ┌─────────────────┐       │  counter    │
         │  Gửi xong frame │       └──────┬──────┘
         │  thành công!    │              ▼
         └─────────────────┘       ┌─────────────────┐
                                   │  Counter > 16?  │── YES → Abort + báo lỗi
                                   └──────┬──────────┘
                                          │ NO
                                          ▼
                                   ┌─────────────────────────┐
                                   │  Binary Exponential     │
                                   │  Backoff: đợi random   │
                                   │  0 to (2^n - 1) slots  │
                                   └─────────────────────────┘
```

### 4.2 Binary Exponential Backoff — Thuật toán "đợi bao lâu"

Khi collision xảy ra:
- Lần 1: chọn random 0 hoặc 1 slot time
- Lần 2: chọn random 0, 1, 2, hoặc 3 slot times
- Lần 3: chọn random 0 đến 7 slot times
- ...
- Lần n (n ≤ 10): chọn random 0 đến (2ⁿ - 1) slot times
- Lần 11-15: giữ nguyên range = 0 đến 1023 slot times
- Lần 16: **BỎ CUỘC** — báo lỗi lên layer trên

**Slot time:**
- 10 Mbps: 51.2 μs (512 bit times)
- 100 Mbps: 5.12 μs (512 bit times)
- 1000 Mbps: 4.096 μs (4096 bit times)

### 4.3 Tại sao CSMA/CD không còn cần thiết?

**Câu trả lời: Full-duplex và Switch!**

| Thời kỳ | Thiết bị | Kết nối | CSMA/CD |
|---------|----------|---------|---------|
| 1980s-1990s | Hub (repeater) | Half-duplex, shared medium | BẮT BUỘC |
| 2000s+ | Switch | Full-duplex, dedicated links | KHÔNG CẦN |

Khi mỗi port trên switch là một **collision domain riêng**, và link chạy **full-duplex** (gửi và nhận đồng thời trên 2 cặp dây khác nhau), không bao giờ có collision nữa. CSMA/CD vẫn tồn tại trong chuẩn IEEE 802.3 nhưng thực tế đã "nghỉ hưu".

**Trong thực tế:** Bạn vẫn có thể thấy half-duplex và collision trên các mạng cũ dùng hub, hoặc khi autonegotiation bị lỗi (duplex mismatch — 1 bên full-duplex, 1 bên half-duplex).

## 5. Autonegotiation — Hai thiết bị "bắt tay" thương lượng

### Ví dụ đời thường: Gặp người nước ngoài

Khi bạn gặp một người lạ, hai người tự động "thương lượng" ngôn ngữ: bạn thử tiếng Anh, họ gật đầu — OK, nói tiếng Anh. Nếu không hiểu, thử tiếng Pháp... Autonegotiation cũng vậy — hai thiết bị mạng tự động tìm ra "ngôn ngữ chung tốt nhất" (tốc độ + duplex mode).

### 5.1 Cơ chế hoạt động — Fast Link Pulse (FLP)

Autonegotiation được định nghĩa trong **IEEE 802.3u (Section 28)**, sử dụng **Fast Link Pulse (FLP)** bursts:

```
Normal Link Pulse (NLP):     ─┐  ┌─     Mỗi 16ms ±8ms (chỉ duy trì link)
                               │  │
                               └──┘
                               
Fast Link Pulse (FLP):  ─┐┌┐┌┐┌┐┌┐┌─    Burst of 33 pulse positions
                          ││││││││││     (17 clock + 16 data positions)
                          └┘└┘└┘└┘└┘
```

**FLP burst** chứa 1 **Link Code Word** (16-bit) encoding khả năng của thiết bị:

```
Link Code Word (Base Page):
┌─────┬─────┬─────────────────────────────────┬────┬────┬────┐
│ S4  │ S3  │ S2  S1  S0  A7  A6  A5  A4  A3 │ A2 │ A1 │ A0 │
│     │     │     Technology Ability           │    │    │    │
└─────┴─────┴─────────────────────────────────┴────┴────┴────┘
 Bit15  Bit14        Bit13 ←──── Bit0
```

### 5.2 Priority Resolution — Chọn mode tốt nhất

Khi 2 thiết bị trao đổi capabilities, mode cao nhất được chọn theo thứ tự ưu tiên:

| Ưu tiên | Mode | Tốc độ + Duplex |
|---------|------|-----------------|
| 1 (cao nhất) | 1000BASE-T Full Duplex | 1 Gbps FD |
| 2 | 1000BASE-T Half Duplex | 1 Gbps HD |
| 3 | 100BASE-TX Full Duplex | 100 Mbps FD |
| 4 | 100BASE-TX Half Duplex | 100 Mbps HD |
| 5 | 100BASE-T4 | 100 Mbps HD |
| 6 | 10BASE-T Full Duplex | 10 Mbps FD |
| 7 (thấp nhất) | 10BASE-T Half Duplex | 10 Mbps HD |

### 5.3 Parallel Detection — Khi 1 bên không hỗ trợ Autoneg

Nếu thiết bị bên kia không hỗ trợ autonegotiation (ví dụ: NIC cũ chỉ phát NLP), thiết bị có autoneg sẽ:
1. Phát hiện chỉ có NLP (không phải FLP)
2. Dùng **Parallel Detection** — detect tốc độ dựa trên link pulse type
3. Giả sử **half-duplex** (vì không thể negotiate duplex mode)

**⚠️ Vấn đề thực tế — Duplex Mismatch:**
Khi 1 bên force full-duplex + 1 bên autoneg → bên autoneg sẽ parallel detect và chọn **half-duplex** → kết quả: **duplex mismatch** → gây late collisions, CRC errors, performance rất kém.

### 5.4 Trong thực tế: Kiểm tra autonegotiation

```bash
# Linux — xem negotiated speed/duplex
ethtool eth0

# Output mẫu:
# Speed: 1000Mb/s
# Duplex: Full
# Auto-negotiation: on
# Link detected: yes

# Xem advertised capabilities
ethtool eth0 | grep -A 20 "Advertised link modes"

# Force speed (KHÔNG khuyến khích trừ khi troubleshooting)
ethtool -s eth0 speed 100 duplex full autoneg off
```

## 6. Physical Layer — Các chuẩn cáp và tốc độ

### Ví dụ đời thường: Các loại đường giao thông

- **10BASE-T** = đường làng 1 lane — chậm nhưng đủ dùng
- **100BASE-TX** = đường tỉnh 2 lanes — nhanh hơn đáng kể
- **1000BASE-T** = đường cao tốc 4 lanes — tốc độ cao
- **10GBASE-T** = đường cao tốc 8 lanes — siêu nhanh
- **Fiber optic** = máy bay — nhanh nhất, đi xa nhất, đắt nhất

### 6.1 Bảng so sánh các chuẩn Physical Layer

| Chuẩn | Tốc độ | Cáp | Khoảng cách max | Pairs used |
|-------|--------|-----|-----------------|-----------|
| 10BASE-T | 10 Mbps | Cat 3+ | 100m | 2 pairs |
| 100BASE-TX | 100 Mbps | Cat 5+ | 100m | 2 pairs |
| 1000BASE-T | 1 Gbps | Cat 5e+ | 100m | 4 pairs |
| 10GBASE-T | 10 Gbps | Cat 6a+ | 100m | 4 pairs |
| 1000BASE-SX | 1 Gbps | Multimode fiber | 550m | 2 fibers |
| 1000BASE-LX | 1 Gbps | Single-mode fiber | 10 km | 2 fibers |
| 10GBASE-SR | 10 Gbps | Multimode fiber | 400m | 2 fibers |
| 10GBASE-LR | 10 Gbps | Single-mode fiber | 10 km | 2 fibers |
| 100GBASE-SR4 | 100 Gbps | Multimode fiber | 100m | 8 fibers |
| 400GBASE-DR4 | 400 Gbps | Single-mode fiber | 500m | 8 fibers |

### 6.2 Encoding — Biến data thành tín hiệu

| Chuẩn | Encoding | Giải thích |
|-------|----------|-----------|
| 10BASE-T | Manchester | Mỗi bit = 1 transition (đơn giản, clock embedded) |
| 100BASE-TX | 4B/5B + MLT-3 | 4 bit data → 5 bit code, dùng 3-level signaling |
| 1000BASE-T | PAM-5 | 5 voltage levels (-2,-1,0,+1,+2) trên 4 pairs đồng thời |
| 10GBASE-T | PAM-16 (DSQ128) | 16 levels, cực kỳ phức tạp signal processing |

### 6.3 Tại sao 1000BASE-T cần cả 4 pairs?

Ở 10/100 Mbps, chỉ dùng 2 pairs (1 gửi, 1 nhận). Nhưng ở 1 Gbps:
- Mỗi pair truyền 250 Mbps
- 4 pairs × 250 Mbps = 1000 Mbps
- Mỗi pair truyền **cả hai chiều đồng thời** (hybrid echo cancellation)
- PAM-5 encoding: mỗi symbol mang 2+ bits thông tin

## 7. Ethernet trong AWS — Mapping sang Cloud

### 7.1 Elastic Network Interface (ENI) — "Card mạng ảo"

Mỗi EC2 instance có ít nhất 1 ENI — đây chính là "card mạng Ethernet ảo" trong cloud:

| Khái niệm Ethernet | AWS Equivalent |
|--------------------|---------------|
| NIC (Network Interface Card) | ENI (Elastic Network Interface) |
| MAC Address | ENI MAC address (được AWS assign) |
| Ethernet Frame | VPC packet encapsulation |
| Switch port | VPC subnet attachment |
| VLAN | VPC Subnet / Security Group |
| MTU 1500 | Default MTU trong VPC |
| Jumbo Frame 9001 | Supported trong cùng VPC/Region |
| Autonegotiation | Enhanced Networking auto-detection |

### 7.2 Enhanced Networking — "Gigabit Ethernet" cho cloud

AWS cung cấp **Enhanced Networking** sử dụng:
- **ENA (Elastic Network Adapter)**: Lên đến 100 Gbps
- **SR-IOV**: Hardware-level network virtualization — bypass hypervisor
- **DPDK support**: Userspace networking cho ultra-low latency

```bash
# Kiểm tra Enhanced Networking trên EC2 instance
ethtool -i eth0
# driver: ena  ← Elastic Network Adapter

# Kiểm tra MTU
ip link show eth0
# mtu 9001  ← Jumbo Frame enabled trong VPC
```

**Cluster Placement Group** = đặt EC2 instances cùng rack → bandwidth cực cao (lên đến 100 Gbps), latency cực thấp. Giống như nối 2 máy cùng 1 switch bằng cáp 10G trực tiếp.

## 8. Tình huống thực tế — Ethernet được sử dụng như thế nào?

### Scenario 1: Trong gia đình / quán cafe

**Bạn Minh mở quán cafe** và cần setup mạng cho khách:

```
Internet ──→ Modem ADSL ──→ Router WiFi (có 4 port Ethernet)
                                    │
                        ┌───────────┼───────────┐
                        │           │           │
                   Máy POS      Camera IP    Laptop Minh
                   (cáp LAN)    (cáp LAN)   (cáp LAN)
```

- Router có 4 port **100BASE-TX** hoặc **1000BASE-T**
- Autonegotiation tự detect: camera 100Mbps, laptop 1Gbps
- Mỗi port là collision domain riêng (switch built-in)
- MTU: 1500 bytes (default)
- Frame format: Ethernet II (vì chạy IP/TCP/HTTP)

**Vấn đề thực tế:** Minh cắm camera IP vào và thấy video lag. Kiểm tra `ethtool` thấy port negotiate 100Mbps half-duplex → duplex mismatch! Fix: set camera về autoneg.

### Scenario 2: Trong công ty vừa (50-200 nhân viên)

```
                         ┌─── Core Switch (10G uplink) ───┐
                         │                                 │
              ┌──────────┤                                 ├──────────┐
              │          │                                 │          │
     Access Switch 1     Access Switch 2          Access Switch 3
     (Tầng 1 - Sales)   (Tầng 2 - Dev)          (Tầng 3 - Management)
     48 port 1GbE        48 port 1GbE            24 port 1GbE
     VLAN 10             VLAN 20                  VLAN 30
              │                  │                         │
     ┌────┬────┬────┐  ┌────┬────┬────┐         ┌────┬────┐
     PC   PC   PC   IP  PC   PC   PC   Server    PC   PC   Printer
                     Phone
```

- **Access layer**: 1GbE (802.3ab) đến desktop
- **Uplink**: 10GbE (802.3ae) giữa switches
- **VLAN tagging** (802.1Q) trên trunk links
- **Jumbo Frame** (MTU 9000) cho server-to-server traffic
- **LACP** bond 2x10G uplinks = 20G bandwidth + redundancy

### Scenario 3: Trong Data Center / Cloud Provider

```
┌────────────────────── Spine-Leaf Architecture ──────────────────────┐
│                                                                      │
│    ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐            │
│    │Spine 1 │    │Spine 2 │    │Spine 3 │    │Spine 4 │            │
│    │400 GbE │    │400 GbE │    │400 GbE │    │400 GbE │            │
│    └──┬──┬──┘    └──┬──┬──┘    └──┬──┬──┘    └──┬──┬──┘            │
│       │  │          │  │          │  │          │  │                │
│    ═══╧══╧══════════╧══╧══════════╧══╧══════════╧══╧═══             │
│    (Full mesh 100-400 GbE links)                                     │
│       │  │          │  │          │  │          │  │                │
│    ┌──┴──┴──┐    ┌──┴──┴──┐    ┌──┴──┴──┐    ┌──┴──┴──┐           │
│    │ Leaf 1 │    │ Leaf 2 │    │ Leaf 3 │    │ Leaf 4 │            │
│    │100 GbE │    │100 GbE │    │100 GbE │    │100 GbE │            │
│    └──┬─┬─┬─┘    └──┬─┬─┬─┘                                        │
│       │ │ │         │ │ │                                           │
│    Server Server  Server Server   (25-100 GbE per server)           │
│    Racks  Racks   Racks  Racks                                      │
└─────────────────────────────────────────────────────────────────────┘
```

- **Server NIC**: 25-100 GbE (802.3by, 802.3cd)
- **Leaf-to-Spine**: 100-400 GbE (802.3ba, 802.3bs)
- **Spine-to-Spine**: 400 GbE (802.3bs)
- **Jumbo Frames everywhere**: MTU 9216
- **RDMA over Converged Ethernet (RoCE)**: Cho HPC workloads
- **Flow control**: Priority Flow Control (PFC) — IEEE 802.1Qbb

## 9. Bài tập thực hành

### Exercise 1: Phân tích Ethernet Frame với Wireshark/tcpdump

```bash
# Bắt 10 frames trên interface eth0
sudo tcpdump -i eth0 -c 10 -xx -nn

# Hoặc dùng Wireshark:
# 1. Mở Wireshark, chọn interface
# 2. Bắt vài frame
# 3. Click vào 1 frame → xem chi tiết:
#    - Destination MAC
#    - Source MAC  
#    - EtherType
#    - Payload
#    - FCS

# Bài tập: Identify EtherType
# Frame hex dump:
# 00 1a 2b 3c 4d 5e  00 11 22 33 44 55  08 00  45 00 ...
#  └── Dst MAC ──┘    └── Src MAC ──┘   │Type│  └IP─
#                                        0x0800 = IPv4
```

**Câu hỏi:** Trong frame trên, EtherType `08 00` nghĩa là gì? Payload bắt đầu bằng `45` — byte đầu tiên của IPv4 header, `4` = version 4, `5` = IHL (header length 20 bytes).

### Exercise 2: Kiểm tra và thay đổi MTU

```bash
# Xem MTU hiện tại
ip link show eth0 | grep mtu

# Test maximum MTU không bị fragment
ping -M do -s 1472 192.168.1.1
# 1472 + 8 (ICMP header) + 20 (IP header) = 1500 = Ethernet MTU
# Nếu set -s 1473 → "Message too long" (packet would exceed MTU)

# Thay đổi MTU (cần root)
sudo ip link set eth0 mtu 9000

# Test Jumbo Frame
ping -M do -s 8972 192.168.1.1
# 8972 + 28 = 9000
```

### Exercise 3: Autonegotiation troubleshooting

```bash
# Xem negotiated parameters
ethtool eth0

# Xem advertised vs partner capabilities
ethtool eth0 | grep -A5 "Advertised"
ethtool eth0 | grep -A5 "Link partner"

# Scenario: Link chỉ negotiate 100Mbps thay vì 1Gbps
# Possible causes:
# 1. Cable Cat5 (không đủ cho 1Gbps, cần Cat5e+)
# 2. 1 trong 4 pairs bị đứt (1Gbps cần cả 4 pairs)
# 3. Cable dài > 100m
# 4. Partner device chỉ support 100Mbps

# Test cable quality
sudo ethtool -t eth0 online
```

### Exercise 4: Frame size và collision domain

```bash
# Tạo frame nhỏ nhất (minimum frame 64 bytes)
# IP payload = 64 - 14(MAC headers) - 4(FCS) - 20(IP) - 8(ICMP) = 18 bytes
ping -s 18 192.168.1.1

# Tạo frame lớn nhất (maximum frame 1518 bytes)
ping -s 1472 192.168.1.1

# Xem interface statistics (CRC errors, collisions)
ethtool -S eth0 | grep -E "crc|collision|error"
# hoặc
cat /proc/net/dev
```

### Exercise 5: AWS — Kiểm tra ENI và Enhanced Networking

```bash
# Trên EC2 instance:
# 1. Xem driver (ena = Enhanced Networking)
ethtool -i eth0

# 2. Xem MTU (should be 9001 for Jumbo Frame support)
ip link show eth0

# 3. Test Jumbo Frame giữa 2 EC2 trong cùng VPC
# Từ instance A → instance B:
ping -M do -s 8972 <instance-B-private-IP>

# 4. AWS CLI — describe ENI
aws ec2 describe-network-interfaces --network-interface-ids eni-xxxx
```
