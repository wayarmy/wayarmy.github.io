## 1. Góc nhìn tổng quan {#overview}

### Ví dụ đời thường

OAuth2 giống **dịch vụ valet parking** (đưa chìa khóa cho người khác lái):
- Bạn (Resource Owner) có xe (data)
- Nhà hàng (Client Application) muốn park xe cho bạn
- Bạn KHÔNG đưa chìa khóa nhà (password) cho nhà hàng
- Bạn đưa **valet key** (access token) - chỉ lái được, không mở cốp

OAuth2 = **Authorization** (ủy quyền) - "App này được làm gì?"
OIDC = **Authentication** (xác thực) - "Bạn là ai?" (layer trên OAuth2)

```
┌─────────────────────────┬────────────────────────────────────────┐
│ Flow                    │ Use Case                               │
├─────────────────────────┼────────────────────────────────────────┤
│ Auth Code + PKCE        │ SPAs, Mobile, Server apps (RECOMMENDED)│
│ Client Credentials      │ Machine-to-machine (no user)           │
│ Device Code             │ Smart TV, CLI, IoT (no browser)        │
│ Implicit (DEPRECATED)   │ Don't use (token in URL = insecure)    │
│ Resource Owner Password │ Don't use (shares password)            │
└─────────────────────────┴────────────────────────────────────────┘
```

## 3. Authorization Code + PKCE {#auth-code-pkce}

```
PKCE (Proof Key for Code Exchange) - RFC 7636
Required by OAuth 2.1 for ALL clients

Flow:
1. Client generates: code_verifier (random string)
   Computes: code_challenge = SHA256(code_verifier)

2. Client → Authorization Server:
   /authorize?response_type=code
   &client_id=xxx
   &redirect_uri=https://app.com/callback
   &scope=openid profile email
   &code_challenge=ABC123
   &code_challenge_method=S256
   &state=random_state

3. User authenticates (login page)

4. Authorization Server → Client:
   /callback?code=AUTH_CODE&state=random_state

5. Client → Authorization Server:
   POST /token
   grant_type=authorization_code
   &code=AUTH_CODE
   &redirect_uri=https://app.com/callback
   &client_id=xxx
   &code_verifier=ORIGINAL_VERIFIER

6. Authorization Server verifies:
   SHA256(code_verifier) == code_challenge? ✓
   Returns: { access_token, refresh_token, id_token }
```

## 4. Client Credentials {#client-credentials}

```
For machine-to-machine (no user involved):
Service A → Service B (backend communication)

POST /token
  grant_type=client_credentials
  &client_id=service_a_id
  &client_secret=service_a_secret
  &scope=api:read api:write

Response: { access_token: "...", expires_in: 3600 }
(No refresh token! Just request new one when expired)
```

## 5. Device Code Flow {#device-code}

```
For devices without browser (Smart TV, CLI):

1. Device → POST /device_authorization
   Response: { device_code, user_code: "ABCD-1234", verification_uri }

2. Device displays: "Go to https://auth.example.com/device
                     Enter code: ABCD-1234"

3. User opens browser on phone → enters code → authenticates

4. Device polls: POST /token (grant_type=urn:ietf:params:oauth:grant-type:device_code)
   Until: { access_token: "..." } or timeout

Example: Netflix on new TV, AWS CLI SSO login
```

## 6-10. Tokens, Scopes, Cognito {#tokens}

### Token Types
```
Access Token:
- Short-lived (15min - 1hr)
- Sent with API requests (Authorization: Bearer xxx)
- Contains permissions/scopes
- Opaque string OR JWT

Refresh Token:
- Long-lived (days - months)
- Used to get new access token (without re-auth)
- Stored securely (not in localStorage!)
- Can be revoked
- Rotation: new refresh token each use

ID Token (OIDC):
- JWT containing user identity claims
- sub, name, email, picture, etc.
- For the CLIENT (not for APIs)
- Validates user identity
```

### Scopes
```
Scopes = permissions requested
openid        → Required for OIDC (get ID token)
profile       → name, picture, etc.
email         → email address
offline_access → get refresh token
api:read      → custom scope (read API data)
api:write     → custom scope (write API data)

User sees consent screen:
"App X wants to: Read your profile, Access your email"
```

### AWS Cognito
```
Cognito User Pool = Auth server (OAuth2/OIDC provider)
- User registration, login, MFA
- Social login (Google, Facebook, Apple)
- SAML/OIDC federation
- Hosted UI or custom UI
- JWT tokens (ID, Access, Refresh)

Cognito Identity Pool = Token exchange
- Exchange Cognito/Social token → AWS credentials
- Authenticated & Unauthenticated roles
- Federated identities
```
